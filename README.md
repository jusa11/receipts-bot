# Учёт покупок по чекам — локальный OCR и разбор

Локальный Telegram-бот принимает фото чека, отправляет его в официальный Yandex Vision OCR, затем передаёт OCR-текст модели в Yandex AI Studio вместе с категориями из локальной Excel-выгрузки. Бот показывает черновой разбор для ручной проверки и сохраняет исходные ответы в `data/`. При настроенной интеграции подтверждённые чеки записываются в указанную Google-таблицу.

Telegram работает через long polling: для локального запуска не нужен публичный сервер или webhook. Обрабатываются только Telegram ID из allowlist.

## Требования

- Python 3.11 или новее.
- Токен Telegram-бота от BotFather.
- Yandex Cloud: API-ключ и ID каталога для Vision OCR. Для модели можно заполнить отдельные `YANDEX_CLOUD_API_KEY`, `YANDEX_CLOUD_FOLDER`, `YANDEX_CLOUD_MODEL`; если оставить их пустыми, будут использованы OCR-ключ и каталог.
- Зафиксированный локальный список категорий и типов расчёта в `receipt_bot/data/categories.json`. Он создан из `category.xlsx`; исходный Excel для обычной работы бота больше не нужен.

## Подготовка Google Sheets API

Интеграция с таблицей ещё не включена. Сначала подготовьте тестовую копию таблицы; основную таблицу бот не должен менять во время проверки.

1. В Google Sheets откройте **Файл → Создать копию** и используйте ссылку именно на копию. ID таблицы находится в URL между `/d/` и `/edit`.
2. В Google Cloud Console создайте проект и включите для него **Google Sheets API**.
3. В **IAM и администрирование → Сервисные аккаунты** создайте сервисный аккаунт и скачайте для него JSON-ключ.
4. Откройте JSON локально и найдите значение `client_email`. Поделитесь тестовой таблицей с этим адресом, выдав роль **Редактор**.
5. Поместите JSON-ключ в `secrets/google-service-account.json` в папке проекта. Папка `secrets/` исключена из Git. Не отправляйте JSON-ключ в Telegram и не добавляйте его в `.env`.

Для тестовой копии заполните в `.env` `GOOGLE_SHEETS_SPREADSHEET_ID` и `GOOGLE_SERVICE_ACCOUNT_FILE`. После установки зависимостей перезапустите бота и вызовите `/sheetscheck`: бот прочитает метаданные и заголовки листа, ничего не записывая. Само содержимое ключа передавать не нужно.

## Запуск в Windows PowerShell

```powershell
Copy-Item .env.example .env
```

Заполните `.env`: `TELEGRAM_BOT_TOKEN`, `ALLOWED_TELEGRAM_USER_IDS` (ваш числовой Telegram ID), `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Для разбора моделью укажите ключ и модель в `YANDEX_CLOUD_*` либо оставьте их пустыми для использования ключа и модели по умолчанию. Затем запустите:

```powershell
.\.venv\Scripts\python.exe -m receipt_bot
```

Unit-тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для OCR, Telegram и модели используется стандартная библиотека Python. Интеграция Google Sheets использует `google-auth`; перед запуском установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Учетные данные не следует отправлять в чат или коммитить в Git.

## Сценарий

1. Узнайте свой числовой Telegram ID (например, в настройках Telegram-клиента или через бота, показывающего ID пользователя).
2. Внесите ID в `ALLOWED_TELEGRAM_USER_IDS`, запустите приложение и напишите боту `/start`.
3. Бот вернёт OCR-текст и черновой разбор; неоднозначные позиции будут отмечены.
4. У каждой позиции кнопки показывают название товара и текущую категорию. Можно выбрать категорию из локального справочника, пропустить или вернуть позицию.
5. Кнопка «Подтвердить чек» сохраняет локальный `approved-result.json`; «Отменить чек» закрывает проверку.
6. Проверьте файлы в `data/receipts/<id>/`: `receipt.json`, `ocr-response.json`, `llm-result.json`, `approved-result.json` после подтверждения и исходное фото.

Если OCR уже сохранён, а разбор завершился ошибкой, используйте `/reparse <ID чека>`: бот повторит только вызов модели, без повторной загрузки фото и OCR. При полученном ответе модели его JSON сохраняется рядом как `llm-response.json` для диагностики; файл содержит данные чека и остаётся локальным.

Для повторного показа уже сохранённого разбора с кнопками проверки используйте `/review <ID чека>` — эта команда не вызывает OCR или модель повторно.

Повторная доставка того же Telegram-сообщения не вызывает повторный запрос OCR, если его результат уже сохранён. Ошибку распознавания можно повторить, переслав фотографию новым сообщением. Удаляйте `data/` вручную, если хотите стереть локально сохранённые изображения и результаты.

Поддерживаются фотографии Telegram и отправленные как файл JPEG, PNG или PDF. Vision OCR принимает изображения до 10 МБ и до 20 мегапикселей. Синхронный режим OCR для PDF поддерживает одностраничные документы; для многостраничных PDF понадобится отдельный асинхронный этап.

## Границы текущего этапа

- OCR распознаёт только текст; модель получает категории из статичного локального JSON-снимка. Позже этот источник будет заменён чтением из Google Sheets.
- Модель не определяет окончательный «Тип расчета»: он берётся из справочника. Backend сверяет суммы строк с правилами `кг`/`шт` листа «Продукты» и сумму позиций с итогом чека, отмечая расхождения для ручной проверки.
- Формулы листа «Продукты»: `Тип расчета` — поиск категории в `Справочник!B:C`; итог — `цена за кг × количество` для `кг` или `штук × цена за шт` для `шт`. Backend не пересчитывает значения с неизвестными единицами и не сравнивает цену до скидки с уменьшенной суммой строки.
- При подготовке строки для таблицы тип `кг` конвертирует количество в килограммы и заполняет I/J; тип `шт` заполняет L/M и оставляет J пустым, как указал владелец таблицы.
- Подтверждение пока сохраняет данные только локально. Оно не пишет в Google Sheets.
- Редактирование названия, бренда, количества и цены в Telegram-интерфейсе не предусмотрено; после подключения таблицы такие исправления можно будет вносить в Google Sheets.
- Месяц, неделю и «цену план» бот не заполняет.
- Запись в Google Sheets включается только при заполнении обоих `GOOGLE_*` параметров; текущий `.env` настроен на тестовую копию.
- Передача изображения в OCR выполняется только после отправки фото боту; локальная копия остаётся в `data/`.

## Формат хранения

`receipt.json` содержит Telegram chat/message IDs, время получения, имя файла, статус и OCR-текст. `ocr-response.json` сохраняет исходный JSON Yandex Vision OCR с координатами блоков и строк. `llm-result.json` содержит структурированный черновик от модели. `llm-response.json` сохраняет исходный ответ модели, если он получен. Токены и API-ключи в эти файлы не записываются.

Локальный снимок категорий можно обновить из нового Excel-файла отдельной командой:

```powershell
.\.venv\Scripts\python.exe -c "from pathlib import Path; from receipt_bot.categories import write_static_snapshot; write_static_snapshot(Path('category.xlsx'), Path('receipt_bot/data/categories.json'))"
```
